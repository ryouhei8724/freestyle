OTF の優位性まとめ

  1. オブジェクトストレージ上での ACID。ジョブが失敗しても、書き込み中に読まれても壊れないデータレイクになる
  2. ストレージと計算の分離、マルチエンジン。1つのデータを Spark で ETL し、Trino で BI、Flink でストリーミング、DuckDB でローカル分析、といった使い方ができる。データのコピーが要らない
  3. ロックインの回避。データは Parquet と公開仕様のメタデータなので、エンジンやベンダーを後から乗り換えられる
  4. メタデータのスケーラビリティ。listing が要らず、ファイル単位の統計によるデータスキップが効く
  5. 安全なスキーマ進化とパーティション進化。列の改名や削除、パーティション粒度の変更が、データの書き直しなしにできる
  6. タイムトラベル、ロールバック、ブランチ。ML の再現性、監査、障害時の巻き戻し、WAP による品質ゲートに使える
  7. 行レベルの DML。MERGE／UPDATE／DELETE で、CDC の取り込みや GDPR の削除に対応できる
  8. ストリーミングとバッチの統合。同じテーブルに exactly-once で書き込み、増分で読める
  9. コスト。オブジェクトストレージは安く、計算は使う分だけ払えばよい
タイムトラベルとロールバックの例（Spark SQL） 
-- Delta Lake
SELECT * FROM orders VERSION AS OF 41;
SELECT * FROM orders TIMESTAMP AS OF '2024-06-01 00:00:00';
RESTORE TABLE orders TO VERSION AS OF 41;

-- Apache Iceberg（VERSION AS OF にはスナップショット ID を渡す）
SELECT * FROM orders VERSION AS OF 5781947118336215154;
SELECT * FROM orders TIMESTAMP AS OF '2024-06-01 00:00:00';
CALL cat.system.rollback_to_snapshot('db.orders', 5781947118336215154);
