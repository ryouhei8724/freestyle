一言でいうと

オープンテーブルフォーマット（以下 OTF）は、S3 などのオブジェクトストレージ上にある Parquet の「ただのファイル群」に、メタデータ層（トランザクションログ）を重ねる仕様です。このメタデータには「どのファイルの集合が、どのバージョンのテーブルなのか」が書かれています。これによって、ACID、スキーマ管理、タイムトラベル、行単位の更新といったデータベース並みの機能が、特定のエンジンやベンダーに縛られずに使えるようになります。

本質的な発想の転換は一つだけです。

「テーブルとは何か」の定義
従来（Hive）ディレクトリにいま置かれているファイル全部。状態は暗黙的で、ls（LIST）の結果が真実
OTFスナップショット N に明示的に列挙されたファイル。状態は明示的でバージョン付き。メタデータが真実
KEY IDEA

OTF の利点は、ほぼすべてこの一点から導かれます。

  • 原子性：新しいファイルは、メタデータから参照されるまで存在しないのと同じ。途中で失敗しても読み手には影響しない
  • 分離性：読み手はあるスナップショットを固定して読むので、書き込み中の途中状態を見ない
  • タイムトラベル：古いスナップショットのメタデータが残っていれば、その時点のテーブルを読める
  • listing 不要：ファイルのパスはメタデータに書いてある
  • データスキップ：ファイルごとの統計（min/max）もメタデータにあり、ファイルを開かずに読む対象を絞れる
  • 安全なスキーマ進化：スキーマもメタデータで版管理され、列を ID で識別できる
